## The problem

Films lived in one app, shows in another and football fixtures in a third, and none of them told me when something I cared about was about to air. I wanted one list for everything I watch, and reminders I could trust.

## What I built

A Next.js web app where you follow movies, shows, teams and leagues side by side. It tracks progress down to the episode, sends reminders by email and in the app, shows live scores during matches, and comes with 56 curated "best of" lists to start from.

**Server components first.** Pages render on the server with the App Router; client components only where there is interaction.

**Prisma on Neon Postgres.** A typed schema and migrations, on serverless Postgres that suits Vercel.

**Scheduled jobs for reminders.** Cron routes look for upcoming episodes and fixtures and send notifications.

**One model, two sources.** TMDB and TheSportsDB responses are mapped into one internal model at the edge of the app.

```ts
// app/api/cron/reminders/route.ts (simplified)
export async function GET(req: Request) {
  assertCronSecret(req);
  const due = await db.reminder.findMany({
    where: { sendAt: { lte: new Date() }, sentAt: null },
  });
  for (const r of due) {
    await sendReminder(r);
    await db.reminder.update({
      where: { id: r.id },
      data: { sentAt: new Date() },
    });
  }
  return Response.json({ sent: due.length });
}
```

## Challenges

### Reminders that fire exactly once

Cron runs can overlap or retry. Each reminder records when it was sent, so a repeated run does nothing.

### Rate-limited data sources

Third-party data is cached and refreshed on a schedule instead of on every request.

### A reviewed API surface

Every route checks the session and validates input; the API went through a dedicated security review.
